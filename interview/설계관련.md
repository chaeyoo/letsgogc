# RAPV-Assistant 레포지토리 전수 분석 정리

> **분석 범위**: `/project` 전체 — 소스 약 30개 · 테스트 18개 · 평가 6개 · 규제문서 13건 · 문서류
> **분석 방식**: 실제 코드 기준 전수 확인 (확인된 내용만 수록)

---

## 1. 프로젝트 개요 (Asset Overview)

**RAPV-Assistant**는 제약 **RA(인허가)·PV(약물감시) 담당자용 RAG + MCP Agentic 어시스턴트의 작동하는 MVP**입니다.

### 한눈에 보는 구조

```
사용자 질의 (웹 UI / API)
      │  ← PII 마스킹 (입구 차단)
      ▼
에이전트 (Anthropic tool-use 루프 / PydanticAI 위임 구현 / 오프라인 규칙 라우터)
      │  ← 도구 자율 호출 (최대 6스텝)
      ▼
FastMCP 서버 — 7종 도구
  (규제문서 검색 · 마감일 · 체크리스트 · AE 트리아지 · ICSR 초안 · 문서목록 · 웹검색)
      │
      ▼
결정론적 사후 검증 게이트 (수치·날짜·방향·역할 대조) + PII 마스킹
      │
      ▼
FastAPI / 웹 UI 서빙 (검증 배지 · 출처 카드)
```

### 핵심 특징

| 구성 요소 | 내용 |
|---|---|
| **MCP 서버** | FastMCP 기반, 7종 도구 노출 |
| **에이전트** |  Anthropic tool-use 루프 직접 구현 + PydanticAI 위임 구현 |
| **응답 품질 보증** | 모든 응답이 결정론적 사후 검증 게이트(수치·날짜·방향·역할 대조) + PII 마스킹 통과 |
| **규제문서 코퍼스** | frontmatter 메타(`doc_id`·`version`·`effective_date`·`status`)를 갖춘 마크다운 13건 |
| **버전 인지 검색** | `as_of` 시점 판정 / `superseded`(폐지본) 처리 |
| **운영 안전장치** | 배포 전 preflight 무결성 게이트 + 평가 하네스(`eval/`)까지 갖춘 완결 구조 |

## 4. 재활용 가능한 핵심 자산 및 확장 가이드 (Reusable Assets & Expansion Notes)

### ① 결정론적 사후 검증 게이트
**`src/verify/verifier.py` (+ `eval/verify_eval.py`)**

LLM 답변 속 수치·날짜·방향 한정어·날짜 역할을 **"신뢰 소스(근거 ∪ 결정론 도구 출력 − 질의 에코)"**와 대조하는 924줄 순수 파이썬 모듈.

- 어떤 RA/PV 챗봇에도 **생성 직후 훅**으로 끼울 수 있음
- `verify_eval.py`의 seeded corruption 방식으로 **도입 즉시 자체 탐지율/오탐율 측정 가능**
- **활용법**: `verify_answer(answer, trusted_texts, user_facts, web_texts, citations)` 호출 → `unsupported`/`direction_conflicts`/`role_conflicts`/`superseded_cited` 라벨을 UI 경고 배지로 노출

### ② PV 규칙 엔진 3종 세트
**`src/pv/triage.py` + `causality.py` + `coding.py` + `report.py`**

중대성 판정(기한 계산 포함)·WHO-UMC 인과성 제안·MedDRA 방식 3계층 코딩·ICH E2D 최소요건 검증이 **MCP/LLM 의존성 없는 순수 함수**라 그대로 이식 가능.

- **활용법**: `SERIOUSNESS_CRITERIA`와 `_TERM_DICT`를 자사 SOP·MedDRA 라이선스 사전으로 교체하고, 규정 근거는 REG-005 자리에 실제 고시를 인제스트해 `basis` 부착 패턴 유지
- 사망 완곡어 열거·다의어 강등 같은 **한국어 실무 오탐 대응이 주석으로 남아 있어** 확장 시 회귀 방지 가이드가 됨

### ③ MCP 도구 계약 패턴 + PII 레닥터
**`src/mcp_server/server.py` + `src/pv/redactor.py`**

"docstring=도구 설명서, 자유 텍스트 인자 전건 마스킹, 조용한 빈 결과 대신 `{"error","expected/available"}` 명시 계약, Tools·Resources·Prompts 3 primitive" 패턴은 사내 시스템(전자문서·KAERS 연동·DMS)을 MCP화할 때 그대로 템플릿이 됨.

- redactor는 **한국 특화**(주민번호 성별코드 1–8, +82, 구분자 대칭) 정규식 마스킹으로, NER 기반(Presidio 등) 교체 자리를 인터페이스로 고정
- **활용법 — 새 도구 추가 시 3규칙**:
  1. docstring에 "언제 쓰는 도구인지 / 언제 다른 도구인지" 명시
  2. 모든 str 인자에 `redact()`
  3. 오류는 명시 계약
  → 이 3규칙만 지키면 기존 에이전트·검증 게이트에 **무수정 연결** 가능

### ⚠️ 확장 시 유의점 (코드에 명시된 경계)

| 항목 | 유의 사항 |
|---|---|
| 코퍼스 | 데모용 **가상 문서**(frontmatter disclaimer 명기) → 실제 고시로 교체 필수 |
| `ra_tasks.json` 마감일 | **시한부 데이터** — 2026-10-13 이후 preflight 실패하도록 설계됨 |
| Abstention 문턱 (0.19/0.28) | 리랭커·코퍼스 변경 시 **재보정 필요** (`agent.py` L37–50의 재보정 절차 참조) |

## 5. 교차 연관 정리 — 앞뒤 내용을 잇는 설계 원칙 (Cross-Reference Synthesis)

문서 곳곳에 흩어져 등장하는 요소들을 관통하는 원칙별로 묶으면, 이 레포의 설계 철학이 5가지로 수렴합니다.

### 원칙 1. "LLM은 오케스트레이션, 계산은 결정론 도구" 분업
- **선언**: `triage.py` 헤더 (④ Agentic)
- **구현**: PV 규칙 엔진 4종이 순수 함수 (① 직무 자산 ↔ 재활용 자산 ②)
- **효과**: LLM 의존성이 없으므로 오프라인 라우터(`_chat_offline`)에서도 동일 판정 가능(③ AI Pre-processing), 검증 게이트의 "신뢰 소스"에 결정론 도구 출력을 편입할 수 있음(⑤)

### 원칙 2. 검증은 "차단"이 아니라 "사람의 최종 확정을 빠르게"
- **판정 계층**: caveat 강제 부착 + 코딩 3계층 + missing/followups (③ HITL)
- **답변 계층**: `verify_answer` 4축 검증 → 경고 배지 부착, 차단 없음 (⑤ ↔ ③ UI 배지)
- **운영 계층**: `GateStats` → `/health` 계기판으로 경고율 감시 (⑤ 관측성 ↔ ③ 모니터링)
- **메타 계층**: `verify_eval.py`가 검증기 자체를 seeded corruption으로 검증 (⑤) — "검증기의 검증"까지 닫힌 루프

### 원칙 3. 조용한 실패 금지 — 명시적 계약
- 날짜 형식 오류 → 조용한 폴백 금지 + caveat (① 컴플라이언스 검증)
- `as_of` 오류 → `{"error","expected"}` (① ↔ MCP 계약 패턴)
- 마감일 오타 → `{"error","available":[...]}` (② D-day 자동화)
- 도구 실패 → `is_error` 되먹임으로 에이전트 자가 정정 (기술 현황표 Agentic)
- 근거 부족 → abstention 문턱으로 답변 회피 (④ RAG)
- 기동 자체 → preflight 실패 시 `exit 1` (⑤)
→ **입력 검증부터 기동 게이트까지 전 계층에서 "자신 있는 오답"을 구조적으로 차단**

### 원칙 4. PII 심층방어 3중 + 로깅 최소화
- 에이전트 입구 / MCP 도구 인자 / Prompt primitive의 **3중 마스킹** (②)
- 원문 비보존 — 유형·건수 summary만 (②)
- 마스킹 전 계층은 **길이만 로깅** (③ Data Intake), flow 로그는 **마스킹 이후 계층만** 텍스트 기록 (⑤ 관측성)
- preflight가 **마스킹이 실제 작동하는지 자가 테스트** (⑤) — 안전장치의 무결성까지 기동 조건화

### 원칙 5. 버전·시점 인지가 전 계층 관통
- 코퍼스 frontmatter(`version`/`effective_date`/`status`/`superseded_by`) (①)
- 청킹 시 버전 메타 보존 (④ 청킹)
- 검색 시 `as_of` 판정·폐지본 기본 제외 (④ 버전 인지 검색)
- 답변 검증 시 폐지본 인용 감지 → 경고 배지 (⑤ 4축 중 ④번 축)
- preflight의 폐지 체인 무결성 검사 (⑤)
- REG-013 폐지본이 이 전 경로의 **테스트 픽스처** 역할 (①)

### 보너스: 평가(eval)가 하이퍼파라미터의 "출처"
- 리랭커 페널티 0.3/0.055 ← `sweep.py`/`stats.py` 재현 (⑤ ↔ ④ 리랭킹)
- abstention 0.19/0.28 ← 실측 분포 보정 + 재보정 절차 주석 (④ ↔ 확장 유의점)
- 검증기 탐지율/오탐율 ← seeded corruption meta-eval (⑤)
→ **매직 넘버가 없고, 모든 수치에 산출 근거와 재보정 경로가 문서화**되어 있음
